# VF-009 - Reusable operator console

Status: implemented in the isolated working copy; local automated checks
passed. Live VF-003 and owner manual acceptance remain pending. See
`docs/vf-009-acceptance.md`.
Product repository and revision: isolated `vf-003-voice-playground` working copy
based on `dcc59c9`, with preserved unstaged VF-003 edits.
Source backlog item: operator foundation handoff, 2026-09-26.
Outcome: an installation can operate real browser sessions through a reusable
console without a client-specific fork or fabricated telephony data.

## Context and dependencies

- Required predecessor and evidence: VF-003 migration, server-owned session
  status and event records, pinned agent version, role checks, and worker events.
  Synthetic integration tests pass; live audio acceptance is separate and open.
- Architecture: `AGENTS.md`, `docs/product.md`, `docs/architecture.md`,
  `docs/decisions.md`, `docs/sessions.md`, and the foundation handoff.
- Open product decisions: audio recording, retention defaults, cross-operator
  visibility, and listen-in. Initial behavior retains no audio, uses the pinned
  30-day transcript default, keeps existing admin/all and operator/own access,
  excludes viewers, and offers no listen-in. These are implementation defaults,
  not owner agreements.

## Scope

- Included: left navigation for real modules; overview counts; live board
  organized by canonical session state; searchable, cursor-paginated history;
  per-session Conversation, Events, Logs, Metrics detail; bounded sanitized
  diagnostic records; validated per-installation branding defaults and per-user
  saved board view; two-second polling; server-side role filtering.
- Excluded: Numbers inventory/routing (VF-005), business tool execution (VF-004),
  tests/reports (VF-007), actual log-sink ingestion, live listen-in, audio
  recording, arbitrary state dragging, and a no-code dashboard builder.
- Ordered steps: define migration and API contracts; add server queries and
  diagnostic writes; add console shell and pages; add view persistence; run
  synthetic role, pagination, concurrency, and retention checks; document
  behavior and manual acceptance.
- Contracts: migration `0004_operator_console`; bounded `session_diagnostics`
  and `operator_views`; `/api/console/*` read and saved-view endpoints; stable
  cursor order `(created_at,id)`; canonical statuses remain unchanged. Brand
  defaults use validated deployment environment settings, separate from DB
  per-user views.

## Manual acceptance

1. Create synthetic admin and two operators in a disposable installation, publish
   one agent, and open two browsers as separate operators.
2. Start a session from each browser; confirm two cards, separate IDs, version
   pins, state changes, details, and eventual history results.
3. Interrupt and disconnect one conversation; confirm accurate labels, errors,
   and each user's access limits. Try viewer and anonymous URLs.
4. Save a board view, reload, and confirm it affects presentation only. Run a
   second isolated installation with different brand variables; compare UI and
   databases. Stop both stacks without deleting non-disposable data.

## Risks and unresolved questions

- Live audio and timing remain dependent on VF-003 manual acceptance.
- Worker registration/health cannot be inferred from an enabled agent; the
  initial overview must label worker readiness as unverified until a real
  health/capacity signal exists.
- Structured stdout is not a queryable log sink. Console Logs initially show
  only bounded, sanitized diagnostic records linked to sessions.
