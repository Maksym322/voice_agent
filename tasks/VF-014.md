## Scope

1. Add validated, nonsecret installation identity and data-lifetime metadata,
   with persistent mode as the safe default. Make identity and a conspicuous
   disposable-data notice visible before login and in the signed-in shell. In
   disposable mode state that accounts/history are temporary; expose configured
   expiry when supplied, without inventing one for an ordinary installation.
2. Add a validated server-controlled SESSION_COOKIE_NAME setting, preserving
   `vf_session` by default for backward compatibility. Use it consistently for
   login, request lookup and logout. Each isolated preview must receive a unique
   cookie name; document distinct names for persistent installations sharing a
   hostname. Reject invalid names and never accept a client-selected namespace.
3. Configure existing isolated-stack helpers to declare disposable identity and
   lifetime. Do not move developer helper code into the product dashboard.
4. Document persistent stop/restart versus disposable teardown and produce a
   short owner verification guide. No schema migration is expected; justify any
   additive migration if genuinely needed, and preserve existing data.

Excluded: live server changes, backup restoration of real data, account recovery,
registration, database reset, pruning, paid voice calls, log sinks, business
integrations, merging or deployment. Never pass a real installation to a test
helper that deletes its volume. Do not inspect or copy real .env files.
